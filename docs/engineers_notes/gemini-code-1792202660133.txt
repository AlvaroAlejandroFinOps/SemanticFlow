PLAN DE REINGENIERÍA TÉCNICA: HARDENING DE SEGURIDAD, DETERMINISMO ZERO-DIFF
Y BLINDAJE DE PRODUCCIÓN DESDE EL IDE (SMaC)
PROYECTO: SemanticFlow
OBJETIVO: RESOLVER VULNERABILIDADES CRÍTICAS, GARANTIZAR DETERMINISMO EN GIT,
          VALIDAR DIRECT LAKE Y CONTROLAR CALIDAD DE EXPRESIONES DAX
================================================================================

1. OBJETIVO Y ALCANCE
--------------------------------------------------------------------------------
Implementar salvaguardas de seguridad, determinismo y control de esquemas para
asegurar que el uso de SemanticFlow dentro del IDE (por ingenieros de datos y
asistentes de IA) sea robusto, auditable e inmune a vulnerabilidades de inyección,
path traversal o contaminación en repositorios Git:
  a) Sanitizar accesos al filesystem y erradicar riesgos de Path Traversal en la
     selección de empresas/perfiles.
  b) Implementar ordenamiento canónico estricto (Zero-Diff Invariant) en todos
     los emisores de código (TMDL, PBIP, dbt, JSON) para evitar diff noise en Git.
  c) Prevenir la fuga o ingesta de secretos en el contexto del agente LLM.
  d) Blindar modelos y medidas contra "Semantic Injection" y alucinaciones en
     fórmulas DAX mediante validación léxica de tokens.
  e) Extender las reglas algorítmicas del Quality Gate (cQS) con verificación de
     compatibilidad con Direct Lake y detección de antipatrones VertiPaq.

Todas las rutas son relativas a la raíz del repositorio local SemanticFlow.

FASE 1: HARDENING DE SEGURIDAD Y CONTROL DE ENTRADAS (INPUT SANITIZATION)
--------------------------------------------------------------------------------
1.1 Prevención de Path Traversal en el orquestador:
    - Archivo: artifacts/SemanticFlow/run_pipeline.py
    - Acción:
      * Crear la función de validación estricta:
        ```python
        import re
        from pathlib import Path

        def sanitize_company_id(company_id: str) -> str:
            if not re.match(r"^[a-zA-Z0-9_-]+$", company_id):
                raise ValueError(
                    f"Identificador de empresa inválido '{company_id}'. "
                    f"Solo se permiten caracteres alfanuméricos, guiones y guiones bajos."
                )
            return company_id
        ```
      * Al resolver las rutas de entrada y salida:
        ```python
        safe_company = sanitize_company_id(args.company)
        input_dir = (Path("artifacts/SemanticFlow/inputs/companies") / safe_company).resolve()
        base_inputs = Path("artifacts/SemanticFlow/inputs/companies").resolve()
        
        if not input_dir.is_relative_to(base_inputs):
            raise PermissionError("Acceso no autorizado fuera del directorio de inputs.")
        ```

1.2 Blindaje contra secretos en perfiles corporativos e inputs:
    - Archivo: schemas/project_governance.schema.json y company_profile_template.yaml
    - Acción:
      * Añadir regla de validación de propiedades que rechace claves con nombres sensibles:
        `^(?!.*(secret|token|password|bearer|api_key|private_key)).*$`

        - Tokens Bearer (`Bearer eyJ...`)
        Si se detecta coincidencia, detener el pipeline con código de salida 1 y mensaje:
        `[SECURITY ERROR] Se detectó una posible credencial o secreto hardcodeado en los inputs.`

FASE 4: QUALITY GATE (cQS) EXTENDIDO PARA DIRECT LAKE Y FINOPS VERTIPAQ
--------------------------------------------------------------------------------
4.1 Regla de Compatibilidad con Microsoft Fabric Direct Lake (Regla D-011):
    - Archivo: src/core/quality/rules.py
    - Acción:
      * Crear la regla `DirectLakeCompatibilityRule`:
        - Verificar que las entidades de tipo `FACT` que operan sobre Direct Lake
          no posean atributos con tipo `DATETIME` sin separación fecha/hora (causa común
          de caída de Direct Lake a DirectQuery por discrepancias V-Order).
        - Verificar que no existan relaciones activas de tipo Many-to-Many (`N:N`),
          ya que saturan el motor de paginación VertiPaq en SKUs F64 o inferiores.
        - Penalización: -15 puntos en `cQS` si se detecta N:N no justificado.

4.2 Regla de Antipatrones DAX VertiPaq (Regla D-012):
    - Archivo: src/core/quality/rules.py
    - Acción:
      * Crear la regla `VertiPaqPerformanceRule`:
        - Detectar uso de `FILTER(ALL('Tabla'), ...)` sobre tablas con cardinalidad
          estimada mayor a 1 millón de registros, sugiriendo `KEEPFILTERS` o `CALCULATETABLE`.
        - Detectar filtrado cruzado bidireccional en relaciones que involucran hechos,
          alertando riesgo de bucle de ambigüedad.
        - Severidad: `WARNING` si no es crítico, penalización -5 puntos en `cQS`.
